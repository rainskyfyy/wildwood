## 1. 目标

实现类饥荒核心联机机制 — **客户端预测 + 服务端校正** + **100ms 插值 + 隐藏窗口**。
解决"60Hz 客户端输入 vs 20Hz 服务端 tick"造成的视觉延迟,让 4 人小队感受到丝滑操作。

## 2. 验收标准(原文)

来自飞书任务拆分表 M3.1:

1. **20Hz tick 100ms 内到达客户端** — 服务端 50ms tick × 网络 RTT < 100ms
2. **客户端预测 ≤ 1 帧误差** — 60Hz 本地应用,无网络等待
3. **偏差 > 32px 触发 100ms 插值 + 隐藏** — 校正期不抖动穿模
4. **权威位置 1:1 一致** — reconcile 后客户端位置 = 服务端位置

## 5. 关键设计

### 5.1 Predictor(客户端预测器)

- **输入队列**:每个预测输入记入 `pending[]`,携带 `seq` / `dx` / `dy` / `t_ms`
- **立即应用**:`predict(dx, dy)` 同步更新本地 `_current_pos`,返回 InputRecord
- **重模拟**:`reconcile(auth_pos, acked_seqs)` 丢弃已 ack 输入,从 auth_pos 重新应用剩余
- **偏差检测**:`|re_simulated - _current_pos_before_reconcile| > 32px` 触发 Correction
- **总是同步**:`_current_pos` 切到 re_simulated(下次 predict 基础正确)

### 5.2 Interpolator(100ms 插值)

- **纯函数**:`display_pos_at(t_ms)` 线性插值 start → target
- **隐藏窗口**:`is_hidden_at(t_ms)` 在 [start, start + 100ms] 内返回 true
- **完成检测**:`is_complete(t_ms)` 在 t ≥ start + 100ms 返回 true

### 5.3 AuthState(服务端校验)

6 条规则:
1. **幂等 seq** — 相同 seq 重复 ack 不再应用
2. **单轴超速** — |dx| > 1 或 |dy| > 1 拒绝
3. **对角线归一化** — length > 1 自动 normalize
4. **速率限制** — 60Hz 上限,超频拒绝
5. **越界** — 超出 WORLD_HALF_BOUND 拒绝
6. **NaN/Inf 保护** — facing / dx / dy 任一非有限值拒绝

### 5.4 Hub 20Hz tick

- `Hub.TickCount()` 公开接口(给压力测试用)
- 每次 tick:遍历房间 → ApplyInput(已校验) → 累积 WorldDelta → 20Hz 广播
- **关键修复**:recv 成功后清 20ms 短 deadline,避免 startReadPump 拿不到下一帧

### 5.5 NetworkClient(GDScript)

- `WebSocketPeer` 收发
- `_physics_process` 60Hz 读 input → predictor.predict → 60Hz 发送 C2S_PlayerInput
- `_process` 20Hz+ 收 S2C_WorldDelta → predictor.reconcile → 启动 Interpolator
- 公开 API:`connect_to_server / is_ready / get_display_pos / is_hidden / shutdown`

### 5.6 PlayerController 集成

- 默认手动模式(M2.1 行为不变)
- `enable_network_mode(client)` 切换到网络模式:
  - `_physics_process` 仅算朝向,不再本地位移
  - `_process` 从 client.get_display_pos() 同步位置
  - 校正期 sprite.visible = false
