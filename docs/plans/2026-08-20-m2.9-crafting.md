# M2.9 合成系统 Implementation Plan

> **For Agent:** 红→绿→commit 节奏跑通;不要并行跨任务;每步交付可跑通的最小增量。

**Goal:** 实现 30+ 配方（工具/装备/食物/建筑）的合成系统,工作台/烹饪锅作高级配方门槛,缺料标红 + 无工作站时配方灰显,合成 ≤ 400ms 反馈。

**Architecture:**
- **核心合成数据 + 算法** 放 `core/abstract/crafting/`(Python 纯逻辑,零外部依赖,A/B 通用层):
  - `schemas.py` — Recipe / Ingredient / CraftingResult / StationType + 版本号
  - `recipe_book.py` — 30+ 配方表(按类别:工具/装备/食物/建筑)+ 类别查询 API
  - `crafting_engine.py` — `check_can_craft(recipe, inventory_view, station_probe)` / `craft(recipe, inventory_view, station_probe, sink)`
  - `inventory_view.py` — Inventory 抽象接口(只读契约,供 M2.2/M2.13 集成)
  - `station_probe.py` — StationProbe 抽象接口(只读契约,供 M2.3 集成)
  - `__init__.py`
- **GDScript 薄包装** `core/abstract/crafting/crafting.gd` 同步语义
- **测试** 全部走 pytest(`tests/unit/test_crafting.py`),沙箱内可跑;GDScript 静态检查
- **Demo 场景** `scenes/crafting_demo.tscn` + `scripts/crafting_demo.gd`(参考 M2.1 风格),`project.godot` main_scene 切换

**Tech Stack:** Python 3.10+（核心逻辑+测试）+ GDScript（薄包装+UI）+ pytest

## 范围边界

**M2.9 包含:**
- Recipe / Ingredient / StationType / CraftingResult schema + 版本号兼容
- 30+ 配方表(至少:工具 8+ / 装备 6+ / 食物 10+ / 建筑 6+)
- 合成引擎:`check_can_craft` / `craft` / 反馈时间
- 工作台/烹饪锅门槛:StationType 枚举(无 / 工作台 / 烹饪锅 / 两者) + StationProbe 接口
- 缺料标红:UI 状态计算返回 `missing_ingredients: list[Ingredient]`
- 无工作站灰显:UI 状态计算返回 `blocked_reason: str | None`
- 性能:单次 craft < 50ms(预算 400ms,留 8x 余量);30+ 配方全表 can_craft < 50ms
- 30+ 配方全表存在性测试(回归保护)

**M2.9 不包含(留给后续):**
- 实际库存变动持久化(M2.6 / M2.13)— M2.9 通过 InventoryView 抽象接口解耦
- 实际建造物放置(M2.3)— M2.9 只产 `CraftingResult`,M2.3 接走"建筑类"
- 联机同步(M3.x)— 单机版先打通,接口预留
- 真实美术资产(M2.14)— UI 用 ASCII / 颜色占位
- 工作台/烹饪锅的"放置"逻辑(M2.3)— M2.9 只问 "附近有 X 吗?",放给 M2.3 实现 StationProbe

## 关键约束(已锁定)

- **配方 ID 命名**:`craft.<category>.<name>` 全小写下划线(如 `craft.tool.axe` / `craft.food.cooked_berries`)
- **StationType**:枚举 `NONE` / `WORKBENCH` / `COOKPOT`(无"两者",需要工作台 + 烹饪锅就标 WORKBENCH + 显式声明"需双站",M2.9 暂不引入"两者"配方;M2.14 后可扩展)
- **材料缺料标红**:`check_can_craft` 必返 `missing_ingredients: list[Ingredient]`,空列表 = 全有
- **无工作站标红**:返 `blocked_reason: str | None`,非 None 时按钮灰显
- **合成反馈时间预算**:400ms(M2.9 验收 ③),内部目标 < 50ms
- **配方可发现性**:`RecipeBook` 暴露 `all()` / `by_category(cat)` / `by_station(st)` / `find_by_id(rid)`

## Task 4: CraftingEngine — check_can_craft / craft(RED→GREEN→COMMIT)

**Files:**
- Create: `core/abstract/crafting/crafting_engine.py`
- Modify: `tests/unit/test_crafting.py`

**Step 1: 写失败测试(check_can_craft 各种场景)**
- 全有材料 + 工作站到位 → can_craft=True,missing=[],blocked=None
- 缺料 → can_craft=False,missing 含缺料项
- 有材料但无工作站 → can_craft=False,blocked="requires_<station>"
- 全空库存 → missing=所有 ingredients
- 未知配方 → 抛 ValueError
- recipe 不存在 → 抛 KeyError(`find_by_id` 返 None 时由 check 抛)

`craft(recipe, inv, station, sink)`:
- 不可合成 → 抛 CraftingError
- 可合成 → 调 `inv.consume` 每个 ingredient + `sink.add` 结果,返 CraftingResult
- 任意 consume 失败 → 中断,回滚已扣的(补偿)

**Step 2: 跑红**

**Step 3: 写最小实现**
- `CraftingError(Exception)`
- `CraftingEngine` 类:
  - `check_can_craft(recipe, inv, station) -> CheckResult`
  - `craft(recipe, inv, station, sink) -> CraftingResult`
- `CheckResult = dataclass(can_craft: bool, missing: tuple[Ingredient, ...], blocked: str | None)`
