# M2.4 生存属性系统实施计划

> **For Agent:** 高级开发工程师端到端实施。TDD 流程(红-绿-重构),小步 commit。

**Goal:** 实现 Wildwood 4 维生存属性(HP/饱腹/精神/温度)30Hz tick 推进,外部条件驱动,警示/速度/幻象三个 modifier 接口暴露给 M2.1 移动控制器和 M2.5 死亡监听。

**Architecture:**
- A/B 通用层(纯 Python stdlib)实现核心推进逻辑,与引擎解耦
- Godot GDScript 薄壳镜像公式(不引入子进程通信,降低复杂度)
- 数据语义沿用 M1.4 既有 `PlayerCurrentState` 字段边界(hp/hunger/sanity/temperature),但**不直接 import M1.4**(M1.4 在另一分支未合并)
- 30Hz tick 与渲染解耦(方案 §3.4);与 M2.1 移动控制器通过 modifier 接口解耦
- 5 个独立 unit test 模块覆盖数据模型 / tick 推进 / 状态判定 / 速度 modifier / 极端边界

**Tech Stack:** Python 3.10+ stdlib + pytest / GDScript(Godot 4.3 客户端)/ Git

**依赖:**
- M2.1 移动控制器(在跑,**不阻塞 M2.4 主体实施**,通过 modifier 接口解耦)
- M1.4 数据层字段语义(参考,不耦合)

**验收标准复述(任务描述):**
1. 4 维属性实时更新(30Hz)
2. 警示动效 < 30% 触发
3. 温度 < 0°C 减速 50%
4. 精神 < 30% 幻象 shader 启用

**性能预算:** 单次 tick(4 维推进 + 3 个 modifier) < 0.1ms(纯 Python,1000 玩家场景下)

- 创建 SurvivalSystem(stats, context) → `tick(1/30)` 不抛错

## 关键设计决策

1. **不依赖 M2.1**:在独立分支 `feat/m2.4-survival` 上做,M2.1 完成后做集成。modifier 通过接口暴露,不直接调用移动控制器。
2. **不依赖 M1.4 import**:M1.4 在另一分支,本任务不复用其代码,只复用字段语义边界。
3. **30Hz tick**:固定 dt=1/30,外部按物理帧调用,内部累计时间(防止丢帧漂移)。
4. **温度边界**:方案 §2.1 "温度极端减速" + 任务描述 "温度 < 0°C 减速 50%",采用 < 0°C → 0.5 modifier;> 35°C → 0.7。
5. **警示动效**:`is_critical()` 返回 True 是必要条件,**实际触发**交给 UI 层(本任务只暴露接口)。
6. **幻象 shader**:`should_show_illusion()` 返回 True 是触发条件,**实际 shader 启用**交给渲染层(本任务只暴露接口)。
7. **HP 衰减触发**:饥饿归零 + 温度极端 + 精神归零三个条件独立触发(任一即扣 HP)。
8. **死亡**:HP <= 0 → `is_alive = False`,停止 tick 推进,等 M2.5 复活机制接入。
9. **GDScript 镜像公式**:本任务只交付 Python 实现 + 公式镜像 GDScript(无 GUT 测试,等 M2.1 + M2.5 接入时再补)。
10. **性能预算**:单次 tick < 0.1ms(纯 Python,简单数学);实测 1000 玩家 × 1s tick 应 < 50ms。
