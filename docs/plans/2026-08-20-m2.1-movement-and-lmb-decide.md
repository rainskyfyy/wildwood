> **For Agent:** 把每条任务按 red→green→commit 节奏跑通;不要并行跨任务;每步交付可跑通的最小增量。

**Goal:** Godot 4.3 客户端实现 WASD/方向键 8 方向移动（60 FPS 平滑、200ms 内响应）+ 鼠标左键 (LMB) 在射程内自动判别 移动/攻击/采集 三类目标,10 场景用例 100% 命中,sprite 朝向正确。

**Architecture:**

- **PlayerController(GDScript)** 持有 Position / Facing / Speed,处理 WASD 输入 + 朝向计算
- **World(GDScript)** 维护玩家 + 占位资源/敌人目标(target_type 标 "gather"/"attack"/"none")
- **M2.1 Demo 场景** `scenes/m21_demo.tscn` + `scripts/m21_demo.gd`,接住主流程,默认 entry 改 m21_demo
- **测试** 全部走 Python pytest(`tests/unit/test_lmb_decide.py`),沙箱内可跑;GDScript 端做静态检查

**Tech Stack:** Godot 4.3 / GDScript(客户端) + Python 3.10+(核心判别逻辑与测试) + pytest

## LMB 智能判别 规则(已锁定)

| 输入 | 判别 |
|------|------|
| 无候选目标(全是 None) | **MOVE** 到点击点 |
| 范围内最近目标 = attack 类型(且距离 ≤ 移动+攻击射程) | **ATTACK** 最近 attack 目标 |
| 范围内最近目标 = gather 类型(且距离 ≤ 移动+采集射程) | **GATHER** 最近 gather 目标 |
| 范围内有 attack 也有 gather | **ATTACK 优先**(战斗威胁 > 资源) |
| 点击点无任何目标在射程内 | **MOVE** 到点击点(试图靠近) |
| 距离 > 移动射程 但有目标在攻击/采集射程 | **MOVE** 到射程内,落地后再 ATTACK/GATHER(本次只返 MOVE) |
| 0 候选 + 点击点不可达(纯几何阻挡) | **MOVE** 仍返(引擎层去做碰撞;纯逻辑不卡) |

**距离度量**:`euclidean`,32 像素 = 1 米(M2.6 / M2.7 共识)。
**默认参数**(可在 World 配置,不在 M2.1 暴露):`move_range=4.0米`,`attack_range=2.0米`,`gather_range=1.5米`。

## Task 6: PlayerController(GDScript)— WASD + 朝向

**Files:**
- Create: `scripts/player_controller.gd`

**Step 1: 实现控制器(纯 GDScript,不依赖场景)**
- `@export var speed: float = 4.0` (米/秒)
- `_physics_process(delta)`: 读 input 向量,normalize,`position += dir * speed * delta * TILE_SIZE_PX`(32 像素 = 1 米)
- 8 方向:不锁对角(W=0,1 都有,Vector2 自然对角)
- `_process`: 根据 velocity 方向算 facing
  - 左/右:`flip_h`
  - 上/下:不 flip,优先记 `last_vertical`(饥荒/星露谷惯例 — 横向 4 帧 + 上下 2 帧,本期 sprite 上下用临时占位,先 flip_h 正确)

  - `position` 改动在 `_physics_process`(60 Hz = 16.67ms 步长,远低于 200ms 预算)

    - GATHER: 打印 "GATHER target=X" + 朝向朝目标(临时视觉反馈:画一根蓝线)
- UI overlay(简易 Label,左上角):当前 action / target / 玩家世界坐标
- ESC:退出
